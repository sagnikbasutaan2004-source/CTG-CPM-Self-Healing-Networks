System Architecture
Five layers.
One coherent decision pipeline.

Each layer feeds its output into the next. Telemetry becomes a risk assessment, risk becomes a set of projected futures, and futures become a structured recommendation backed by formal game theory.

Layer 01
Ingestion
Data Ingestion and Streaming
Live host metrics from psutil (CPU, RAM, Disk I/O, Process Table) and synthetic 5G optical transceiver telemetry (OSNR, Laser Bias, Temperature, Packet Loss). Events published to Apache Kafka at localhost:9092 with honest status reporting — no emulator substitution when no broker is reachable.
psutil Apache Kafka telemetry_collector.py kafka_telemetry_streaming.py
Layer 02
Topology GNN
Graph Neural Network Cascade Risk Assessment
A PyTorch GNN (GCN or GraphSAGE) processes the network topology graph, using live telemetry as node features. Outputs per-node anomaly probabilities and identifies downstream cascade risk nodes. The model_kind field in every prediction report honestly identifies which architecture produced the result.
PyTorch GCN / GraphSAGE gnn_topology_model.py gnn_model.pt
Layer 03
Generative AI
Counterfactual Time-Series Generation
A conditional Diffusion denoising model (Diffusion-TS) generates parallel 20-timestep projections under each candidate intervention. Scenarios are tagged with their generator (diffusion or heuristic), health score, and a note marking them as projections — never as live-verified outcomes. Heuristic fallback uses explicit exponential decay models.
Diffusion-TS Denoising Score Matching counterfactual_engine.py diffusion_ts_model.pt
Layer 04
Game Theory
Multi-Agent Game-Theoretic Decision Engine
Four formal mechanisms coordinate agent decisions: VCG auction allocates tasks by maximizing social welfare (DSIC property). Shapley values compute exact marginal feature attribution. Backward induction solves the Subgame Perfect Equilibrium of the investment-bargaining game. Nash equilibrium analysis prevents conflicting agent strategies.
VCG Auction Shapley Values Backward Induction SPE Nash Equilibrium game_engine.py
Layer 05
Interface
LLM Diagnostics, REST API, and Dashboard
The Groq LLM API translates mathematical outputs into structured JSON diagnoses with severity, root cause, remediation steps, and expected outcome narrative. Flask serves five REST endpoints. The web dashboard presents live telemetry, diagnosis panels, counterfactual scenarios, and the SPE game tree interactively.
Groq LLM API Flask app.py llm_diagnostician.py NETCONF/YANG PowerShell
Algorithm Reference
Six algorithms.
All mathematically grounded.

Every decision in the pipeline is produced by a formally-specified algorithm. No black-box heuristics, no hardcoded constants.

01 — TOPOLOGY
Graph Neural Network
GCN + GraphSAGE — Cascade Risk Prediction
Aggregates neighborhood telemetry features across the network graph to compute per-node anomaly probabilities. Detects which nodes are anomalous and which downstream nodes are at cascade failure risk.
GCN: H' = sigma(D^-1/2 A D^-1/2 H W) GraphSAGE: h_v = sigma(W . CONCAT( h_v, MEAN_{u in N(v)} h_u ))
Architecture reported honestly as model_kind in every prediction output.
02 — GENERATIVE AI
Diffusion-TS Generator
Conditional Time-Series Counterfactual Projection
Generates parallel future telemetry trajectories conditioned on each candidate intervention using denoising diffusion. Stable training with no mode collapse. Tagged as diffusion or heuristic depending on weight availability.
Reverse: x_(t-1) = (1/sqrt(a_t)) * (x_t - ((1-a_t)/sqrt(1-a_bar_t)) * eps_theta(x_t, t, c)) + sigma_t*z T = 50 diffusion steps, seq_len = 20
Every scenario tagged: generator, projected_stabilized, note: PROJECTION ONLY.
03 — ROOT CAUSE
Shapley Value Attribution
Cooperative Game Theory — Feature Importance
Computes exact marginal contributions of each telemetry feature to the anomaly score across all possible feature subsets. Satisfies Efficiency, Symmetry, and Null Player axioms. Dynamic characteristic function built from live Z-scores.
phi_i(v) = SUM over S in subsets(N\{i}) [|S|!(|N|-|S|-1)!/|N|!] * [v(S union {i}) - v(S)] v(S) = SUM_{m in S} (z_m^1.6) * 15.0
Efficiency: sum of all phi_i equals v(N). This is attribution, not validated causal proof.
04 — TASK ALLOCATION
VCG Auction Mechanism
Dominant-Strategy Incentive Compatible Task Assignment
Allocates diagnostic, bargaining, and execution tasks to the three agents by maximizing total social welfare. VCG payments ensure agents truthfully report their capabilities — strategic misrepresentation is never profitable.
a* = argmax_a SUM_i v_i(a_i) Payment_i = max_{a' without i} SUM_{j!=i} v_j(a'_j) - SUM_{j!=i} v_j(a*_j) Bids derived dynamically from telemetry stress level per run.
Guarantees DSIC: truthful bidding is the dominant strategy for every agent.
05 — BARGAINING
Backward Induction SPE
Extensive-Form Game — Subgame Perfect Equilibrium
Models the investment-remediation bargaining between the system (P2) and the remediation agent (P1) as a 3-stage sequential game. Backward induction finds the strategy profile that is a Nash Equilibrium in every subgame.
P2: choose Investment (High/Low) P1: propose Split (Fair/Greedy) P2: respond (Accept/Reject) Parameters derived dynamically from live OSNR, Temperature, and Laser Bias per telemetry sample. Default SPE: (Low, Greedy, Accept) Payoff: (u1=13.0, u2=0.0)
Parameters change each run. SPE payoffs reflect current telemetry, not fixed constants.
06 — COORDINATION
Nash Equilibrium
Normal-Form Game — Conflict Resolution
Constructs a 2x2 payoff matrix from counterfactual health scores and intervention costs. Best-response analysis finds the pure-strategy Nash Equilibrium preventing agents from choosing conflicting strategies simultaneously.
u_A_high = h*0.22 - cost*1.4 + stab*3.0 u_B_eco = h*0.24 - cost*0.4 Find (r,c) where: r = argmax_r u_A(r,c) for each c c = argmax_c u_B(r,c) for each r Intersection = Nash Equilibrium
Payoff matrix built dynamically from live counterfactual projection scores each run.

User Guide
Four steps to
a recommendation.

No configuration required to start. psutil reads from this machine automatically. Kafka and LLM API are optional and the system reports their status honestly when unavailable.

Step 01 — Select Mode
Choose your telemetry source
Use the mode selector to switch between Live Laptop Host Telemetry (real psutil hardware data from this machine) and 5G Optical Backhaul (synthetic transceiver simulation). Both modes run through the same decision pipeline.
Step 02 — Observe
Read the live telemetry gauges
The four metric cards update every 2 seconds. Colors shift from blue/purple to red when a metric exceeds its safe threshold. The status badge at the top-right shows whether the dynamic anomaly detector has flagged a condition.
Step 03 — Inject
Simulate a fault condition
Click Inject Failure Anomaly to stress-scale the telemetry and activate anomaly mode. In Laptop mode, CPU and memory are scaled upward. In 5G mode, OSNR drops below threshold and laser bias elevates. The status banner turns red.
Step 04 — Decide
Generate a remediation recommendation
Click Generate Remediation to run the full pipeline. The diagnosis panel appears with Shapley attribution bars, counterfactual scenario scores with generator provenance, the SPE game tree outcome, and a step-by-step remediation plan. Review the recommendation and apply it manually if appropriate.
Understanding the Output
Shapley Attribution Bars
Percentage contribution of each telemetry feature to the anomaly score. A feature with 50% attribution is the dominant driver of the detected condition. This is statistical attribution, not validated causal root cause.
Counterfactual Projections
Projected health scores under each candidate intervention. "Projected Stable" means the final projected health score exceeds 40/100. Generator badge shows whether a learned Diffusion model or an explicit heuristic trajectory model produced the projection.
SPE Game Tree Outcome
The Subgame Perfect Equilibrium path from the investment-bargaining game. Investment level, proposal strategy, and response are determined dynamically from live telemetry parameters each run. Payoffs (u1, u2) are game-theoretic utility values.
Deployment Status
Always "not_deployed" in the prototype. The remediation command (NETCONF/YANG XML for 5G, PowerShell for Laptop) is parameterized with live telemetry values and displayed for human review. No command is automatically pushed to any device.
